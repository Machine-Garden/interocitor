Interocitor / WebAuthn Blob Store

Multiple application keys, different custody preferences

This page maps three application labels—stored, protected, and enforced—to browser storage and WebAuthn custody primitives. They are demo labels, not browser security levels; the browser decides the available authenticator and verification experience.

Login / mesh credential custody still uses createWebCredentialStore(...). This example covers the additional key material your app may need after the user is already in.

Stored label

Default local storage

This key is stored in browser localStorage. It is durable and fast, but it does not ask the browser for a biometric or phone ceremony. 

No stored key yet.
Protected label

Seal a record locally

This store prefers a platform authenticator such as Touch ID, Face ID, or Windows Hello. The stored blob is an exported AES-GCM key owned by the app. 

No sealed record yet.
Enforced label

Sign a token through a different store

This store requests a cross-platform credential with hybrid hints. The browser may use a phone, a roaming security key, another supported flow, or reject the request.
